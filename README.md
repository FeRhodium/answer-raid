# ANSWER RAID · 计算机协会百团大战答题终端

一个炫酷、硬核的**三档难度答题网站**。技术栈:**Svelte 5 (runes) + Vite + TypeScript**,
无后端、无运行时依赖,构建产物是一坨纯静态文件,丢到任何静态托管 / U 盘 / 内网 nginx 都能跑。

```bash
pnpm install
pnpm dev        # 开发预览 http://localhost:5173
pnpm build      # 产物在 dist/
pnpm preview    # 本地起静态服务预览 dist
pnpm test       # 全套验证(类型检查 + 题库 + 引擎 + 构建 + DOM 冒烟)
```

## 玩法:三档递进,越往上越不许犯错

一局 = **三档 × 每档 5 题**,答满一档晋级下一档,通关 ACM 档才算封神。

| 档位 | 名称 | 内容 | 限时 | 不灭次数 | 基础分 |
|---|---|---|---|---|---|
| 01 | **入门档** ENTRY | 阅读题:题干即教材,零基础也能答 | 30s | 2 | 100 |
| 02 | **硬核档** SYSTEMS | 计算机通识热知识,平时关注技术圈才会 | 45s | 1 | 250 |
| 03 | **竞赛档** ACM | 专业方向的概念题 | 60s | 1 | 500 |

面向**有高中数学知识的大一新生**:入门档自带阅读材料、读完就能做,硬核档靠技术圈通识,
竞赛档靠专业概念。全部为选择题,**不需要纸笔、现场能快速作答**。
界面**中英双语**,右上角一键切换(见下文「中英双语」)。

- **不灭次数**:该档内允许答错的次数,**归零立即出局**;晋级时按新档位重置
  → 硬核档与竞赛档**错一题就出局**。
- **连击**:每答对一题连击 +1,**跨档累积**,倍率 `1 + 0.1×(连击-1)` 封顶 **×2.0**;
  答错或超时清零。
- **时间奖励**:`1 + 0.5 × 剩余时间占比`,答得越快乘得越高。
- **超时**:倒计时归零即判定为答错,与选错同等处理并展示原理。
- **评级**:SSS(全程零失误通关)/ SS(通关)/ S(触及 ACM 档)/ A / B / C / D。

每题得分:

```
得分 = 基础分 × 时间系数(1.0 ~ 1.5) × 连击倍率(1.0 ~ 2.0) × 情报折扣(1.0 / 0.4)
```

| # | 考点 | 题面要点 | 答案 |
|---|---|---|---|

每题选项顺序在作答时随机打乱,静态的 `answer` 下标也刻意打散在不同位置。

## 每局都不一样

- **随机抽题**:每局从题库里抽**本局未出现过**的题;某档抽尽后重新洗牌(避开最近一题)。
- **选项打乱**:每次抽题都会重新打乱 4 个选项的顺序,正确项位置随机 —— 背「选 B」没用。
- 两个机制都在测试里做了统计验证(见下)。

## 反作弊 / 防泄题

页面上**没有任何地方**显示正确答案,答案只存在题目数据里、在作答后才随讲解一起出现。
浏览器里能翻到的只有 `dist/assets/*.js` 里的题库文本(本来就是打印出来发传单的内容),
**不存在「前端藏答案」这类可被利用的漏洞**,因为它压根不需要后端。

## 主题:暗色 CRT / 亮色强光

右上角按钮一键切换(`☀` 表示点了变亮色,`☾` 表示点了变暗色)。

| 主题 | 用途 | 视觉 |
|---|---|---|
| **暗色**(默认) | 室内、晚上 | 原版 CRT:扫描线 + 暗角 + 字符雨 + 辉光 |
| **亮色** | **强光环境**(户外摊位、正午阳光下的屏幕) | 白底高对比;关掉扫描线 / 暗角 / 字符雨 |

亮色不是把暗色反转,做了三件必要的调整:

1. **强调色降亮度提饱和** —— 暗色下用 `hsl(hue 100% 62%)`,放到白底上会糊;亮色改用 `hsl(hue 88% 30%)`;
2. **面板改为不透明** —— 暗色下 `backdrop-filter` + 半透明底色很好看,但亮色下背景会透上来吃掉对比度;
3. **新增 `--on-accent` 令牌** —— 强调色/危险色实心块上的文字,暗色下是近黑、亮色下反过来要用白。

实现要点:

- 两套取值都写在 `src/app.css`,用 `[data-theme='light']` 覆盖 `:root` 的**同一套语义令牌**;
  `tools/theme-test.mjs` 会校验两套令牌**一一对应**(漏一个就会亮色下漏出暗色的值)。
- `--hue` 仍然由 JS 按档位写入,所以三个档位的换色在亮色下照样生效。
- 主题状态在 `src/lib/theme.svelte.ts`(runes 单例),优先级 `?theme=` > localStorage > 系统偏好 > 暗色。
- `index.html` 里有**一段内联脚本在首帧前**就把 `data-theme` 写上 —— 否则亮色用户每次加载
  都会先闪一下暗色。
- 组件里已不存在硬编码的暗色(`#04060a` / `#eafff6` 等),全部走令牌;`theme-test.mjs` 会拦住漏改。

## 中英双语(i18n)

语言开关在**右上角常驻按钮**「🌐 EN」(中文界面)/「🌐 中」(英文界面)——
按钮上显示的是**点了会切过去的**语言,所以对局中途也能随时切换。

- **语言优先级**:`?lang=` 查询参数 > localStorage > 浏览器语言 > 默认中文。
  查询参数这条路是给自动化测试与分享链接用的,例如 `index.html?lang=en` 直接以英文开局。
- **界面文案**:全部集中在 `src/lib/i18n.svelte.ts` 的字典里,组件用 `msg()` / `fmt()` 取。
  带插值的句子写成 `Msg((p) => ...)`,渲染时再求值,所以切语言时连「剩余不灭 1」这类
  动态文案也会立刻跟着变。字典的 zh / en 两组 key 由 `pnpm test:bank` 校验必须一一对应。
- **题库**:不走字典。每题自带 `zh` / `en` 两份文本(`prompt` / `options` / `explain`),
  抽题时按当前语言摊平成渲染用的结构,所以渲染层完全不用感知语言。
  **`answer` 下标两种语言共享** —— 改选项时两边必须同步增删,否则 `pnpm test:bank` 会报错。
- **题目标签**:`tags` 是写死在题目里的中文键(如 `补码`),展示时走字典的 `tag.*` 命名空间
  (`tagLabel()`)。漏译时英文界面会显示成 `补码!` —— 宁可难看也不静默漏中文,
  而且 `pnpm test:bank` 会直接把漏译标出来。
- **加一种语言**:在 `LOCALES` 里加代码、补一份字典(含 `tag.*`)、给题库每题补一份文本即可;
  `tools/ts-resolve.mjs` 已经能处理带 runes 的 `.ts`,新语言不需要碰构建配置。

### 视觉与音效

- **配色由档位色相驱动**:引擎把当前档位的 `--hue` 写进 `:root`,入门档 152(绿)、
  硬核档 45(琥珀)、竞赛档 320(品红),晋级时整站配色**平滑切换**。
- 全站等宽字体 + CRT 扫描线 + 暗角 + 噪点 + 字符雨 + 标题 glitch 重影。
- 音效**全部现场合成**(方波/三角波/锯齿波 + 带通噪声):悬停、作答、正误、晋级、
  结算、超时 glitch,外加一层 55/110/165 Hz 的缓慢「呼吸」底噪。右上角可静音,偏好会记住。
  - 底噪的 55 Hz 在笔记本/手机外放上基本发不出来,所以额外叠了 110/165 Hz 的中频层,
    否则听起来就像没声音。
  - **AudioContext 必须等用户手势再创建**:在 `onMount` 里就 `new AudioContext()` 会被
    浏览器自动播放策略挂起,底噪节点建好也一声不响。现在改由一次性手势监听解锁,
    且每次取用都会确认 `resume()`(`pnpm test:dom` 里有探针守着这两条)。
  - **静音开关的状态用 runes 镜像了一份**:`audio.ts` 是普通模块,模板直接读它的变量时
    Svelte 追踪不到 —— 点了按钮状态变了、图标却不重绘,看起来就像「按钮点不动」。
- 尊重 `prefers-reduced-motion`。

## 验证:`pnpm test`

这个项目有 **303 项自动断言**,分五层,全部离线跑:

| 命令 | 覆盖 | 断言数 |
|---|---|---|
| `pnpm check` | svelte-check + tsc,严格模式 0 error | — |
| `pnpm test:bank` | 题库结构(15 题 / 4 选项 / 答案下标分布 / 图表合法性)、**中英双语完整性**(两种语言选项数一致 / 无空文本 / 字典 key 与**题目标签**一一对应)、摊平不丢字段、选项打乱统计、独立复刻的一局推进、评级阈值 | 100 |
| `pnpm test:theme` | **直接读 app.css 源码**:两套主题的令牌必须一一对应、亮色取值确实够亮、组件里不许残留硬编码暗色、首帧预置脚本与 CRT 开关都在位 | 19 |
| `pnpm test:store` | **直接 import 真实的 quiz 商店引擎**(Svelte 编译 runes),精确驱动:晋级 / 不灭扣减与重置 / 连击与计分公式 / 锦囊全部分支 / 超时判定 / 一局内不重复抽题 / **中英抽题本地化** / 重开与回标题 | 85 |
| `pnpm test:dom` | 把 **dist 里真实构建产物**加载进 happy-dom 并真的点按钮:自检→标题→开局→用锦囊→答题→判定→扣命→出局结算→重开,含键盘作答、**中英语言切换**、**主题切换(含 CRT 与字符雨的开关)**、**静音开关(图标必须真的变)**与 **AudioContext 探针** | 99 |

两处诚实的说明:

1. `test:dom` **没有**做「连对 5 题 → 晋级幕」的完整 DOM 走查。原因是题与选项顺序都是
   运行时随机的,测试若要在作答前知道正确项就必须复刻应用的抽样实现 —— 那是实现细节,
   复刻只会带来假阳性。**晋级流程本身已由 `test:store` 直接驱动真实引擎覆盖**(它作答后
   能从引擎读到 `answerIndex`,因此 100% 准确),晋级幕的渲染则由组件逻辑与代码审查保证。
2. `test:bank` 里的「一局推进」是**独立复刻**的规则实现(不 import 引擎),用来交叉验证
   引擎的档位/不灭/计分是否自洽;而 `test:store` 驱动的是真引擎。两份实现互相印证。

## 改造成你们社团的版本

1. **换题目**:改 `src/lib/data/questions/*.ts`,每题结构见 `src/lib/data/types.ts`。
   加题后同步把 `ROUNDS_PER_TIER`(`src/lib/data/types.ts`)按需调整。
   `explain` 会直接展示给参赛者,建议写清「为什么对 + 最诱人的错项错在哪」。
2. **换二维码**:`src/lib/components/Result.svelte` 里的 `.qr` 目前是 ASCII 占位,
   换成 `<img src="/qr.png" alt="招新群二维码">` 即可(`public/` 放图)。
3. **换配色**:改 `src/lib/data/tiers.ts` 里各档的 `hue` 即可,全站跟着变。
4. **调难度**:同一文件里的 `allowMiss` / `timeLimit` / `baseScore`。

## 部署

`pnpm build` 后把 `dist/` 整个目录丢到任意静态服务的子路径即可(`vite.config.ts` 里
`base: './'` 已配成相对路径,不依赖根目录)。
